## 1. Steering & Prompting Techniques

Getting better output from any agent — the most transferable skill on this list (works in Cowork, Chat, and Codex too).

- 🔗 **Boris Cherny's team-workflow steering tips** — [howborisusesclaudecode.com](https://howborisusesclaudecode.com/) — the tips not already elsewhere in this file: one Claude writes the plan while a second reviews it as a staff engineer (re-plan when things go sideways); harsh-reviewer prompts ("grill me on these changes," "prove this works"); voice prompting because typed prompts get simplified to save keystrokes; Claude as a learning tool via explanatory output and codebase diagrams.
- 📌 **Interview-me tool or skill** — Claude interrogates you to extract tacit knowledge (Hannah's "ask-user-question to push me on my thinking" prompt). ↔ §2 Context Engineering
- **Anti-sycophancy prompt (verbatim from the doc):**
  > "You are a sparring partner, not an assistant. Default to honest over agreeable. When I share a plan, idea, or decision: identify the weakest assumption, steelman the opposite view, and tell me what I'm missing before you tell me what's working. If something is genuinely good, say so, but earn it. Don't lead with validation. When I push back on your critique, don't fold. Hold your position until I give you a real counter-argument. Only back down if I've actually changed something, not just restated myself more confidently."

## 4. Subagent Orchestration

- 🔗 **When and how to use multi-agent systems (Anthropic official)** — [claude.com blog](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them) — multi-agent wins in exactly three cases: context protection, parallelization, specialization — otherwise single-agent, at 3–10× token cost; decompose by *context boundaries*, not roles (planner/implementer/tester splits create a "telephone game"); the verification subagent is the one pattern that works everywhere. - 🔗 **When multi-agent graphs beat one prompt: a 40-task benchmark** — [Aakash Gupta](https://www.linkedin.com/posts/aagupta_s-ai-productmanagement-share-7495348468484599811-AwWx/) + [follow-up post](https://www.linkedin.com/posts/aagupta_everyones-been-hyping-graphs-over-prompts-share-7496794895219621888-fssr/) + [article](https://www.news.aakashg.com/p/graphs) (library paywalled) — graphs won 25 of 40 PM tasks. ## 5. Automation: Hooks, Loops, Routines & Goals

From prompting to systems that run themselves — and reach you anywhere.

- 🔗 **"You are the loop right now. Design one instead."** — [Aakash Gupta on Peter Steinberger](https://www.linkedin.com/posts/aagupta_peter-steinberger-keeps-posting-the-same-share-7484456668831838208-GcHs/) — a timer vs. a true loop: scheduling automates the trigger, not quality control; loop anatomy: trigger → skill loading → maker agent → checker agent with explicit gates → delivery; the PM's job becomes writing concrete verification criteria.
- 🔗 **Loops, not prompts (Boris Cherny + Peter Steinberger)** — [Aakash Gupta](https://www.linkedin.com/posts/aagupta_boris-cherny-built-claude-code-he-says-he-share-7484118334272282624-DEmC/) — a real loop verifies its own output against success criteria before surfacing anything; use a separate verification agent (creators inflate their own grades); prediction: PMs go from ~20 prompts/day to running 10–15 standing loops. ↔ §7 Evals (verification gates)
- 🔗 **Loop engineering replaces prompt engineering** — [Aakash Gupta on Shubham Saboo (Senior AI PM, Google)](https://www.linkedin.com/posts/aagupta_shubham-saboo-a-senior-ai-pm-at-google-share-7477018635149103104-whCe/) — five loop components: Trigger → Action → Proof (score vs. prior version) → Memory (commit winners, revert losers) → Stop (escalate to human on weak evidence); fixes "skill rot" via continuous testing + auto-rollback — maps onto this workspace's `evals-advisor` + evals.md pattern. ↔ §7 Evals (verification gates)
- 📺 **How to write AI agent loops in Claude Code and Codex (Claire Vo, How I AI)** — [video](https://www.youtube.com/watch?v=JoXbk2fm7jM) + 🔗 [writeup](https://www.chatprd.ai/how-i-ai/how-i-ai-designing-ai-agent-loops-in-claude-code-and-codex) — "a loop is just a prompt that fires itself": taxonomy of four trigger types (heartbeat, cron, hook, goal loop — the newest first-class citizen); two live builds: a daily Claude Code loop that finds PRs open >12h and either fixes them via subagents or Slack-escalates, and a weekly Codex automation that spawns its own goal-looped subagents to validate undocumented skills; design loops like onboarding an employee (what to check, how often, what output, who to escalate to); watch token cost on nested loops. ## 7. Evals

- 🔗 **Asymmetry of verification and the verifier's rule** — [Jason Wei](https://www.jasonwei.net/blog/asymmetry-of-verification-and-verifiers-law) — the theory under this file's verification gates: many tasks are far easier to check than to solve, and up-front work (answer keys, test cases) widens the gap; "the ease of training AI to solve a task is proportional to how verifiable the task is." ## 13. AI Security & Risk

Agents ingesting untrusted content are an attack surface — extra weight given MCP connections to Slack/email/Jira at a HIPAA-regulated company.

- 🔗 **Prompt injection targets agents, RAG pipelines, and model routers** — [VentureBeat](https://venturebeat.com/security/prompt-injection-is-exploiting-enterprise-ais-biggest-design-flaws-by-targeting-agents-rag-pipelines-and-model-routers) — six attack vectors: agent hijacking, RAG supply-chain poisoning, cross-model injection, context-overflow, memory poisoning, router manipulation. Real incidents: EchoLeak (CVE-2025-32711, CVSS 9.3 — zero-click Microsoft 365 Copilot exploit via one crafted email), Slack AI channel exfiltration; CrowdStrike reports AI-enabled attacks up 89% YoY. Defenses: constrain permissions, segment untrusted content, human approval on tool invocation, validate RAG provenance — treat LLMs as untrusted interpreters.
- 🔗 **Vendor lock-in & governance risk** — [VentureBeat on Claude Managed Agents](https://venturebeat.com/orchestration/anthropic-wants-to-own-your-agents-memory-evals-and-orchestration-and-that-should-make-enterprises-nervous) — evaluation moving inside the orchestration layer, hosted memory, data residency. ↔ §10 Ecosystem Watch (primary listing)
